# 해피워크 UI/UX 디자인 철학

해피워크는 **행사 현장 단기 근무자**와 **그들을 모으고 관리하는 회사 담당자**가 함께 쓰는 앱이다.
근무자는 카톡 링크로 처음 들어와 휴대폰 하나로 가입·지원·서명·출퇴근·급여 확인까지 끝내고,
담당자는 현장에서 휴대폰으로, 사무실에서 컴퓨터로 모집·확정·출퇴근·정산을 한다. 여러 회사가 한 앱을 함께 쓴다.

이 문서는 화면을 새로 만들거나 고칠 때 따르는 기준이다. 실제 값은 `src/app/globals.css`(색·그림자·움직임·공용 모양)와
`src/components/ui.tsx`·`Icon.tsx`·`Skeleton.tsx`·`LiveNumber.tsx`에 있다. 이 문서와 코드가 다르면 코드를 맞춘다.

---

## 1. 일곱 가지 원칙

### ① 휴대폰이 먼저다 (360px 기준)
- 모든 화면은 **가로 360px 휴대폰**에서 먼저 맞춘다. 넓은 화면은 그다음.
- **옆으로 밀리는 화면은 없다.** 긴 회사명·주소·번호는 `truncate`나 줄바꿈으로 칸 안에.
- **어색한 두 줄 줄바꿈 금지**: 마지막 줄에 한 단어만 남지 않게(`text-wrap: pretty`), 제목은 `balance`,
  한글은 단어 단위로 줄바꿈(`word-break: keep-all`).
- 자주 누르는 것은 **엄지가 닿는 아래쪽**에: 떠 있는 아래 탭(근무자·관리자 모두), 지원하기 바, 채팅 입력칸.
- 누르는 곳은 손가락 크기(높이 36px 이상, 주요 버튼 44px 이상).

### ② 지금 할 일이 맨 위에
- 화면을 열면 **오늘·지금 해야 할 일**이 먼저 보인다.
  - 근무자: 오늘 근무(출퇴근) → 서명할 서류 → 이번 주 근무 → 나머지
  - 관리자: 오늘 현황 → 확인할 일(새 문의 포함) → 인원 부족 → 숫자 → 오늘 행사 → 대기 지원자
- 급하지 않은 것(후기, 알림 설정, 자주 안 쓰는 버튼)은 **아래로 내리거나 '더보기'로 접는다.**
- 같은 성격의 안내는 카드 여러 장 대신 **한 목록**으로 모은다(예: 관리자 '✅ 확인할 일').

### ③ 기다림을 느끼지 않게
- 누르는 즉시 반응: 위쪽 진행 막대, 버튼 눌림, **실제 화면과 같은 모양의 '불러오는 중'**(빛이 쓸고 지나가는 스켈레톤).
- 한 번 연 화면은 30초 동안 휴대폰에 두었다가 **다시 열면 바로** 보여 준다(내가 저장하면 즉시 새로 받아 옴).
- 서버는 서로 상관없는 조회를 **한꺼번에** 한다(차례로 기다리는 횟수를 줄임).
- 자주 바뀌는 화면(문의·출퇴근 현황)은 조용히 자동 새로 고침.

### ④ 실수는 화면이 먼저 막는다
- 되돌리기 어려운 동작은 **두 번 눌러 확인**(대화상자 없이 같은 버튼이 '정말 ~할까요?'로 바뀜).
- 근무 종료처럼 잘못 누르기 쉬운 버튼은 보호하고, 서명 전에는 출근이 잠긴다.
- 겹치는 근무·빠진 계좌·안 올린 사진은 **미리** 알려 준다.
- 오류는 **이유 + 할 일**을 쉬운 말로, 그리고 **복사 버튼**(담당자에게 그대로 보낼 수 있게).

### ⑤ 회사가 여럿이어도 헷갈리지 않게
- 근무자에게 보이는 공고·근무·서류·급여에는 **어느 회사 것인지(🏢 회사 이름)**를 함께 보인다.
- 문의는 회사마다 따로, 대화 목록에서 한눈에. 여러 회사를 맡은 관리자에게는 **다른 회사의 새 문의**를 알린다.
- 회사 사이의 자료는 섞이지 않는다(화면에서 숨기는 것이 아니라 데이터부터 회사별로).

### ⑥ 믿을 수 있게, 필요한 만큼만 보이게
- 개인정보는 필요한 사람에게 필요한 만큼만: 커뮤니티는 별명, 주민번호는 가림, 근무자 명단은 비밀번호로 한 번 더 잠금.
- 숫자는 정직하게: 같은 사람을 두 번 세지 않는다(공고 '확인' 인원), 추정이면 추정이라고 말한다.
- 서류·명세서는 **종이처럼 늘 밝게**(어두운 화면에서도).

### ⑦ 움직임은 의미가 있을 때만, 짧게
- 움직임은 **무엇이 바뀌었는지** 알려 줄 때만: 새 화면이 떠오름, 탭 표시가 옮겨 감, 숫자가 올라감, 완료 축하.
- 길이는 **150~400ms**(화면 전환은 0.3초 안), 끝이 부드럽게 멈추는 곡선(`--ease-spring`, 화면 전환은 `--vt-ease`). 튕기지 않는다.
- **누른 순간 반응**한다: 새 화면을 기다리는 동안 손가락 아래가 가만히 있으면 안 된다(아래 탭 표시는 누르자마자 옮겨 감).
- 휴대폰의 **'동작 줄이기'가 켜져 있으면 모두 끈다**(화면 전환·숫자 효과·반짝임 포함).

## 2. 시각 언어

### 색 — 의미로만 쓴다
| 역할 | 토큰 | 쓰는 곳 |
|---|---|---|
| 글자 | `ink` #191f28 / `sub` #4e5968 / `mute` #8b95a1 | 제목 / 본문 / 보조 정보 |
| 바탕·선 | `bg` #f2f4f6 / `line` #e5e8eb / 흰 카드 | 화면 바탕 / 구분선 / 카드 |
| 강조(행동) | `brand` 600 #2557e8 (50~700) | 주요 버튼, 링크, 선택됨 |
| 전문가 화면 | 같은 `brand` 토큰이 보라(#6a3fe8)로 바뀜 | 전문가·외주 업체 화면 전체 (`data-mode="pro"`) |
| 완료·근무 중 | emerald | 출근함, 지급 완료, 확인된 회사 |
| 확인 필요 | amber | 서명할 서류, 시간 변경 답, 입금 대기 |
| 급함·오류 | rose | 인원 부족, 안 읽은 수, 삭제, 오류 |

- 한 화면에 강조색은 **한 곳에 크게, 나머지는 작게.** 안내 카드는 **옅은 바탕 + 가는 테두리**(굵은 색 테두리 쓰지 않음).
- 그라데이션은 **화면에 하나, 가장 중요한 카드에만**(예: 홈 '오늘 근무가 있어요', 지난 근무 합계).
- 화면 위쪽에 강조색이 아주 은은하게 번지는 배경(전문가 화면은 보라로 따라 바뀜).

### 모양
- 둥근 정도: 카드 **22px**, 큰 강조 카드 24~26px, 버튼·입력칸 **14px**, 작은 버튼 11px, 칩·배지 **완전히 둥글게**.
- 그림자: 카드는 `shadow-card`(아주 옅은 테두리 + 아래로 번지는 그림자), 누를 수 있는 카드는 올리면 `shadow-lift`.
- **유리(glass)**는 화면 위에 **떠 있는 것에만**: 아래 탭, 머리글, 지원하기 바, 맨 위로 버튼, 더보기 시트.

### 글자
- 글꼴: **Pretendard**(앱에 포함, 화면에 쓰인 글자만 내려받음).
- 크기 단계: 화면 제목 24~26px 굵게 → 섹션 제목 18px 굵게 → 카드 제목 16~18px → 본문 15px → 보조 13~14px → 배지 12px.
- 숫자는 자리가 흔들리지 않게 `tabular-nums`. 제목은 글자 사이를 살짝 좁힘(-0.02~-0.03em).
- 입력칸 글자는 16px(아이폰이 화면을 확대하지 않게).

### 아이콘과 이모지
- 화면의 기능 표시는 **같은 굵기의 선 아이콘**(`components/Icon.tsx`, 선 1.9, 글자 색을 따름).
- 이모지는 **대화·알림·안내 문구의 첫 글자** 정도로만 쓰고, 버튼·목록 표시에는 선 아이콘을 쓴다.
- **병아리 캐릭터**는 빈 화면, 이모티콘, 당겨서 새로 고침처럼 마음을 놓이게 하는 순간에만.

## 3. 공용 모양 (globals.css · components)

| 이름 | 언제 |
|---|---|
| `card` / `card-link` | 내용 묶음 / 통째로 눌러 이동하는 카드(누르면 살짝 눌림) |
| `btn-primary` | 화면에서 **가장 중요한 행동 하나**(위쪽이 살짝 밝은 입체 버튼) |
| `btn-soft` / `btn-gray` / `btn-danger` | 보조 행동 / 덜 중요한 행동 / 지우기·취소 |
| `chip` / `chip-primary` | 거르기·빠른 선택, 작은 실행 버튼 |
| `badge` | 상태 표시(모집중·확정·지급 예정 등) |
| `input` / `label` / `hint` | 입력칸 / 이름표 / 칸 아래 도움말 |
| `section-title` | 화면 안 섹션 제목 |
| `glass` | 떠 있는 요소 |
| `SubmitButton` / `ConfirmSubmit` | 보내는 중 표시 / 두 번 눌러 확인 |
| `Skeleton` 계열 | 화면마다 실제 모양을 닮은 '불러오는 중' |
| `LiveNumber` | 숫자가 바뀌면 톡 튐, `countUp`이면 처음에 0에서 올라감 |
| `Flash` | 저장·완료 안내(잠깐 뒤 사라짐, 큰 일은 축하 효과) |
| `Empty` | 빈 화면: 병아리 + **다음에 할 일 링크** |
| `Icon` | 선 아이콘 |

### 화면 뼈대
- **머리글 한 줄**: 로고 · (관리자는 회사 이름/고르기) · 로그아웃. 반투명 유리.
- **떠 있는 아래 탭**(휴대폰): 근무자 `알바 찾기·내 근무·커뮤니티·문의·내 정보`, 관리자 `홈·공고·근무자·문의·더보기`.
  누른 탭 표시가 미끄러지듯 옮겨 감. 넓은 화면의 관리자는 위쪽 메뉴.
- **목록 행**(문의 대화 목록처럼): 둥근 사각 아이콘 · 이름 · 마지막 내용 미리보기 · 시간 · 안 읽은 수.
- **자주 안 쓰는 버튼은 '더보기'**로 접고, 접혀 있을 때는 자리도 차지하지 않게.

## 4. 움직임 (인터랙션)

| 순간 | 움직임 |
|---|---|
| 누름 | 살짝 작아짐(버튼 0.96, 카드 0.985), 아래 탭 아이콘이 톡, **탭 표시는 누른 순간 옮겨 감**(화면을 기다리지 않음) |
| 화면 이동 (아래 탭) | 이전 내용은 0.09초에 흐려지고 새 내용이 6px 아래에서 떠오름 (0.22초) |
| 들어가기 / 돌아가기 | 공고·글·대화 열기는 오른쪽에서, '← 돌아가기'는 왼쪽에서 (`transitionTypes`, 0.3초). 휴대폰 뒤로 가기는 휴대폰이 보여 주는 대로(한 번 더 움직이지 않음) |
| 머리글·아래 탭 | 화면이 바뀌어도 **움직이지 않고, 내용에 덮이지도 않음**(전환 동안 따로 떼어 맨 위에 두는 기준점) |
| 불러오던 회색 자리 → 내용 | 뚝 바뀌지 않고 회색 자리가 걷히며 그 아래 내용이 드러남 (0.16초). 회색 자리는 그 화면 모양 그대로 |
| 같은 화면 거르기·자동 새로 고침 | 움직이지 않음 |
| 숫자 | 처음 열 때 0에서 올라감, 바뀌면 톡 튐 |
| 완료 | 체크가 그려짐·축하 점이 퍼짐·하트가 떠오름(좋아요) |
| 불러오는 중 | 화면 모양 그대로, 빛이 한 번에 쓸고 지나감 |

규칙: 150~400ms(화면 전환 0.3초 안) · 끝이 부드럽게, 튕김 없음 · 누른 순간 반응 · 움직임을 겹쳐 쌓지 않음(목록 차례 등장은 0.15초 안에 모두 시작) · 화면 전환 중에도 누르기는 그대로 · '동작 줄이기'면 끔.

## 5. 글쓰기 (UX 문구)

- **쉬운 한국어, 해요체.** 전문용어·영어 대신 일상어: '로그아웃'은 그대로 두되 '세션 만료' 대신 '다시 로그인해 주세요'.
- 버튼은 **동사로 끝나게**: '지원하기', '출퇴근하러 가기', '답장하기 →'.
- 안내는 **무엇이 · 왜 · 어떻게** 순서로 한두 문장. 예) "서명을 마쳐야 근무 시작 버튼을 누를 수 있어요."
- 오류는 탓하지 않고 할 일을 준다. 예) "이 사진은 열 수 없어요. 다른 사진을 골라 주세요."
- 형식: 날짜 `11/4(수)`, 시간 `09:00 ~ 18:00`, 돈 `82,560원`, 큰 돈 요약 `8.2만`, 전화 `010-1234-5678`.
- 빈 화면은 "없어요"로 끝내지 않고 **다음 행동**을 붙인다. 예) "오늘 예정된 근무가 없어요 · 모집 중인 알바 보기 →"

## 6. 보는 방식 설정

- **글자 크게 보기**(내 정보): 화면 전체 글자와 버튼이 조금 커짐. 이 휴대폰에만.
- **어두운 화면(베타)**(내 정보·회사 설정): 이 휴대폰에만. 밝은 화면은 그대로 두고 켰을 때만 색을 바꾼다.
  새 색 클래스를 쓰면 `globals.css`의 어두운 화면 목록에도 짝을 추가한다. 서류·명세서·QR(`.print-sheet`)은 늘 밝게.
- 인쇄·PDF 화면은 화면용 꾸밈(아래 탭·머리글 등)을 빼고(`no-print`) 종이 모양 그대로.

## 7. 새 화면·기능 체크리스트

1. 360px에서 옆으로 밀리지 않는가, 어색한 두 줄 줄바꿈이 없는가
2. 화면을 열었을 때 가장 먼저 해야 할 일이 맨 위에 있는가
3. 강조색 버튼은 하나인가, 상태색이 의미대로 쓰였는가
4. 불러오는 중 모양(스켈레톤)이 실제 화면과 닮았는가
5. 빈 화면·오류에 다음 할 일이 있는가, 오류는 복사할 수 있는가
6. 되돌리기 어려운 동작은 두 번 눌러 확인하는가
7. 여러 회사 상황에서 어느 회사 것인지 보이는가, 다른 회사 자료가 섞이지 않는가
8. 움직임이 짧고 의미 있는가, '동작 줄이기'에서 꺼지는가
9. 어두운 화면에서 글자가 잘 보이는가(새 색 클래스는 짝 추가)
10. 아래 탭·지원하기 바·채팅 입력칸에 가리지 않는가(`--tabbar-space`)
11. 문구가 쉬운 해요체이고, 버튼이 동사로 끝나는가
12. 테스트(`scripts/qa`)로 동작과 360px을 확인했는가
